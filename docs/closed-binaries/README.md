# Private binaries: what we can't build from source

Generated by `analysis/private-binaries.py` from GL.iNet's official MT2500 images and our latest complete comparison per release. Metadata only: no file from GL.iNet's images is stored here.

A binary is listed when it belongs to a closed package that the recipe copies from the official image (packages built from GL.iNet's published source or from public source are left out), when a public package's file still differs in our best complete build (outside the accepted classes: Samba, Python bytecode, `wg`, kernel version fields), or, for the kernel, when its code differs function by function. Text files (scripts, configuration, Lua source, web files, also gzip-compressed) are left out.

Each cell holds the first 8 hex digits of the file's MD5 in that release (`·`: not in that release or not private there); a value repeated along a row means the binary didn't change; ⚠ marks a binary with sensitive-looking data (keys, certificates, credentials, high-entropy strings), detailed only in the private repository. Full hashes, paths in the firmware bundle and all other metadata are in the per-release files.
